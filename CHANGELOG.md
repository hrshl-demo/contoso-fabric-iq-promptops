# Changelog

Newest first. Every prompt version has one line of the form `` - `<prompt id>` <version>: <what changed> ``; `python -m tools.lint_prompts` checks it. A release turns `## Unreleased` into `## vX.Y.Z — YYYY-MM-DD` (`python -m tools.release prepare`, see `docs/RELEASING.md`); `python -m tools.release lint` checks the structure.

### Pipelines
- Release: `release` workflow (run by hand from the Actions tab) checks the rules, rebuilds the files from the commit, and publishes a GitHub release with the Monthly Business Brief, the ontology brief, the Fabric item definitions, the prompt library and checksums. A dry run is the default. CI builds the same files on every pull request (`release-preview` artifact). Optional **Deploy to prod** (with Publish) deploys only what the last dev deployment that really ran had (a run whose deploy job was skipped does not count) and always loads the data again.
- Deployment (draft, off until `CD_ENABLED` is set, see `docs/SETUP.md`): `cd-dev` deploys to the dev workspace after a merge that changes what is deployed; `capacity` gives status, resume, pause and a guard every 3 hours that pauses a forgotten F4 (a demo hold variable stops it). `tools/cd.py` runs the steps, stops them at a deadline, checks the workspace is on the capacity it pauses, and always pauses the capacity once it has been resumed, also after a failure; it is tested with fakes and against the kit's Fabric mock, not yet against a live tenant. The capacity role needs `write` as well as read, suspend and resume (Microsoft's pause and resume page) and is assigned on the capacity itself.
- Plans: `docs/SETUP.md` (the one-time identity, role, Fabric settings and first runs, each step marked as needing your go) and `docs/PILOT.md` (shortcut and Databricks pilot, costs and decision rules; not started).
- Platform (draft, not run against a live tenant): the `platform` workflow builds everything from blank. `tools/platform.py` creates a storage account as the data source (`infra/main.bicep`, with CI compile and lint), uploads the seed data to it, builds bronze, silver and gold from that copy, creates the F4 (or keeps the one that exists: never resized, never loses an administrator; a person is a capacity administrator by user principal name, a service principal by object id), the workspace and the lakehouse, loads the data, checks the ontology gate and asks a capacity admin to open it while the data loads, and pauses the F4 (also after a failure, an interrupt or a deadline; a capacity deployment still running behind the pause is cancelled and waited for first). `check` is free and read-only and runs before every build; `build` and `destroy` need a typed confirmation, an approver and `main`; `destroy` purges the workspace like the kit's wipe and pauses what it resumed. The last line of defence is `tools.platform rescue`, preceded by a fresh sign-in (an OIDC sign-in lasts about an hour). The capacity guard treats a capacity that does not exist yet as nothing to guard. A cancelled capacity deployment is not trusted to be an undo: the pause waits for a capacity that is still being provisioned, looks for one that appears late, and a deployment that cannot be stopped with no capacity to pause ends in exit 4. `tools/bootstrap.py` scripts the one-time identity (an empty resource group, the app and its main-branch-only trust, an Entra group for the Fabric tenant settings, roles on that resource group only, the repository secrets and variables) as a dry run by default, refuses first, read-only, anything that looks like a mistake (a repository that does not exist, a resource group that is not empty, an app with any federated credential besides the one it is for, a role with the consumer role's name that is not the role this project defines), and onboards a content repository with a least-privilege role on the capacity itself. Docs: `docs/BOOTSTRAP.md`, `docs/PLATFORM.md`, `docs/CONSUMING.md`, `docs/part2/NEW_SESSION_PROMPT.md`.
